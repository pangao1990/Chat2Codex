## 本轮修复

- 停止任务后等待拥有的进程树和 Node 进程句柄都完成退出；Windows `taskkill` 完成后仍需等待退出事件。不能确认清理完成时停止队列，避免新任务与旧进程争用目录。
- 同一测试以最近一次命令回执为准，较早成功不能掩盖后续失败。
- 旧回合输出和权限通知按任务/回合编号过滤，避免覆盖当前报告。
- 深层损坏的上下文、权限记录、累计用量和时间字段在读取时拒绝，不传入 React 导致页面异常。
- 已完成任务不能通过“停止”重新变成可继续执行状态。
- 目录占用检测正确处理文件系统根目录，且不误判名字相近的相邻目录。
- 安装包冒烟保留失败阶段与日志，并记录实际启动耗时；超时阈值保持 45 秒。
- Linux 界面回归等待窄窗口布局完成后再操作侧栏，避免误点重排前的按钮；CI 失败时上传隔离测试截图和诊断。
- RPC 初始化版本随包版本更新；临时浏览器快照、环境文件和签名凭据不纳入提交。

## 公开打包前补充修复

发布准备期间，主分支 CI 再次暴露 macOS 退出时序问题。本地复现确认：`SIGKILL` 后进程短暂处于僵尸状态，进程组存在性探测返回 `EPERM`，约 100 毫秒后收到退出事件，探测返回 `ESRCH`。修复将存在性探测的 `EPERM` 视为仍在运行，继续有界等待；真正发送终止信号被拒绝时仍报错，不能据此放行队列。测试也避免对已退出的单进程 fixture 重复清理。

- 原 Release 构建已在公开发布前取消，版本标签重新指向包含修复的提交后再构建。
- 桌面测试：301 项，300 通过、1 项 Linux 条件跳过、0 失败。
- 进程清理的真实进程检查、瞬态 `EPERM` 回归和拒绝终止信号检查，连续运行 10 次均通过。
- 公开软件包以修复后标签的 Release Actions 附件和校验文件为准。
