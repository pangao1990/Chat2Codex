# 任务工作台

[English](workbench.en.md)

任务工作台与原有 Responses / MCP 桥接是两条独立路径。首页任务使用 ChatGPT 网页规划（可选）和本地 Codex API 执行器；不需要安装旧模型路由、重启官方客户端或配置 MCP Tunnel。

## 开始使用

1. 安装支持 App Server 协议的 Codex CLI。已在本机核验 0.152.1 的初始化、有效配置读取和隔离 API 路由；其他版本应运行连接检查。
2. 打开首页的“连接与执行设置”，填写 OpenAI 执行 API Key、模型和 Codex 可执行文件。macOS/Linux 会搜索常见安装目录；Windows 需要可执行的原生 `codex.exe`，不通过 Shell 执行 `.cmd` 包装器。
3. 保存设置后运行“检查执行连接（不调用模型）”。它检查官方 API 模型目录和本地协议，不证明一次完整模型执行已经成功。
4. 如需 ChatGPT 规划，在程序自己的浏览器窗口登录 ChatGPT。Codex 独立模式可以跳过这一步。
5. 选择项目目录，填写需求与验收条件，预览上下文并开始任务。

API Key 使用操作系统加密存储。Linux 若只能提供 `basic_text` 后端，会拒绝保存；请先配置系统密钥环。首版只支持 OpenAI 官方推理 API，第三方兼容 API 未列入支持范围。网页版所需模型和推理强度由实际账号可用性决定；不支持的强度会显式报错。

## 三种策略

| 选项 | 行为 |
| --- | --- |
| 自动选择 | 使用本地规则评估任务范围、交接大小、网页可用性和是否停滞；阶段边界才重新选择 |
| ChatGPT 规划 | 总体规划和阶段复盘使用网页，Codex 完成实施与测试；网页失效暂停，不静默回退 |
| Codex 独立 | 分析、执行和复盘都由 Codex 完成，不向网页发送任务 |

首页选择器同时更新新任务默认值及当前选中的任务；其他已有任务不受影响。运行中变更在下一阶段生效，已经发出的模型请求不会被倒退撤销。Codex 仍会进行实现所需的推理，ChatGPT 规划不等于关闭执行模型的思考。

自动选择是规则策略，不是已经训练好的成本预测模型。不会为比较成本而把同一任务自动跑两遍，也不会显示无依据的“节省比例”。实际收益需要在相同质量、验收和代码起点下进行对照测试。

## 状态、队列与恢复

- 多个任务按提交顺序排队，首版串行执行，避免争抢浏览器和工作区。
- 同一目录及父子目录不能同时被排队或运行任务占用。
- “阶段结束后暂停”等待当前模型阶段收尾；“停止”请求取消并终止本程序拥有的进程树。已发生的代码修改不会自动回滚。
- 重启后，运行和排队任务进入中断状态，必须明确点击继续，不会偷偷重放。
- 继续使用保存的 Codex 任务，并要求先检查工作区；恢复不会清零累计用量、轮数和时间。
- 如果首次执行前中断、Codex 确认历史尚未生成，只有明确点击继续才会创建恢复任务；仍保留原用量与预算，并先检查现有修改。
- 如达到预算，在设置中明确提高上限后再继续。Token 事件有延迟，上限属于尽力停止阈值，不能当作服务端硬账单上限。
- Codex 的命令/文件权限请求显示在任务详情中，可允许本次或拒绝。其他暂不支持的交互会返回明确错误，让执行器报告阻塞。
- 无有效命令回执支撑的“测试通过”不会自动通过验收。没有适用自动测试的任务可人工验收，并独立记录人工接受。

## 上下文与隐私

预览只自动采集一级目录名称、Git 版本、变更文件列表与差异统计，不自动上传整个仓库。代码不足时规划器应让 Codex 先调查。复盘收到必要的方案、执行摘要与最近命令证据。文件名和命令输出也可能包含私人信息；不要在需求中粘贴密钥。程序会过滤常见密钥形式，这不等于能识别所有敏感内容。

`~/.chat2codex/workbench/tasks.json` 保存需求、计划、任务状态、命令证据与用量；`workbench/executors/<任务编号>/` 保存隔离的 Codex 历史。设置和记录使用原子写入及私有文件权限；记录本身不加密。密钥单独加密保存在 `workbench/api-key.enc`。开发版使用独立的 `~/.chat2codex-dev/`。

首页需求、目录、当前选中任务和补充要求会暂存在窗口的 sessionStorage，切换到登录页或设置页再返回时可继续填写；执行密钥不写入草稿。关闭窗口后的保留行为由 Electron 会话决定，不应把草稿当作备份。

最多保留 200 个任务，事件与命令分别保留最近 200/100 条。删除任务同时清除对应隔离执行历史，保留项目文件。任务报告导出包含需求、项目名称和命令输出；与默认脱敏诊断日志不同，分享前需要检查。任务文件损坏时保留原文件并停止调度，不将损坏视为零任务。

## 用量与费用

- Codex Token 来自执行器的用量事件。缓存输入和推理输出是已有输入/输出的子项，不重复相加。
- 未收到用量事件时显示未知。失败、取消和恢复不会清除已记录用量。
- 网页 Token 使用现有 tokenizer 估算，无法观察网页内部全部用量；未完成且无法计量的网页回合会单独标注。
- API 单价可留空；未知价格显示未知。单价按任务创建时的设置固定，计费以 OpenAI Platform 为准。
- 原桥接的“API 等效价值”只换算网页工作量，不代表真实节省、余额或退款。价格未知的模型继续计 Token，并标明未计入金额的回合。

## 验证与发行

`bun run verify` 覆盖类型检查、单元与集成测试、依赖审计和可搬迁运行时构建；`bun run launcher:smoke:ui` 在真实 Chromium 中以模拟 IPC 检查页面。

真实网页登录＋真实 API 完整执行、限流/过期会话、平台原生权限窗口、系统密钥环及签名安装包，必须按 [发布验证清单](release-validation.md) 单独验收。自动测试和本地协议握手不代表这些真实环境检查已完成。
